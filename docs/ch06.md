# 第6章　大会が生んだ2,500時間超のデータ

閉幕時、準備・訓練と正式競技から得た2,500時間超のデータセットが発表された。規模は、12の応用場面、44種類の作業、100種類超の技能、1万件超の詳細タスクである。成功した最終動作だけでなく、失敗、境界条件、長い作業列、動的な外乱までを含むと説明されている。競技で一度使った経験を、次の学習・評価へ戻すことが構想の中心にある。[[1]](#ref-1)[[2]](#ref-2)

## 6.1 発表された範囲

| 項目 | 発表内容 | 数字の意味 |
|---|---:|---|
| 総時間 | 2,500時間超 | 準備・訓練と正式競技の記録 |
| 応用場面 | 12 | データ側の場面分類 |
| 作業 | 44種類 | 場面内で行う作業単位 |
| 技能 | 100種類超 | 把持、移動、操作などの技能分類 |
| 詳細タスク | 1万件超 | 条件を具体化したタスク単位 |

12の応用場面は、競技プログラムの21の実環境タスク種目を数え直したものではない。大会は競技単位、データセットは利用・学習向けの場面や作業単位で分類しており、公開資料には両者の対応表がない。

## 6.2 映像から長いタスク軌跡まで

発表資料は内容を、生センサデータ、意味アノテーション、タスク軌跡の三層で説明した。これを研究で使う順に並べると、次のようになる。

| 層 | 含まれると説明された内容 | 技術的に可能になる分析 | 利用に必要だが未公表の仕様 |
|---|---|---|---|
| 実行の記録 | 多視点映像、関節運動情報、ロボット／機体状態、タスク結果 | 視点をまたぐ姿勢推定、関節運動と成功・失敗時点の対応、異常の前兆探索 | カメラ校正・同期、関節名と単位、状態項目、時刻基準 |
| 状況と意味 | 失敗例、境界条件、意味意図・行動ラベル、物体認識・検出アノテーション | 成功例だけでなく失敗条件を学ぶこと、意図から動作への分解、対象物別の知覚評価 | ラベル体系、注釈単位、品質管理、境界条件の定義 |
| 長い作業 | 長時間のタスク軌跡、動的外乱を受ける実行 | 作業順序、割込み後の復帰、外乱への耐性、部分成功から最終結果までの評価 | エピソード境界、介入記録、欠損処理、終了条件 |

100 mなら映像、関節状態、機体状態とタイムを同じ時計で重ねることで、加速や転倒の前兆を追える。家庭内サービスなら、洗濯、宅配受取、衣類操作の順序と、割込み後の復帰を一つの長い軌跡として扱える。小売や屋外管理では、商品配置や人・環境の変化を境界条件として付与すれば、同じ方策がどの条件で崩れるかを比較できる。失敗例を成功例と同じスキーマで残すことは、模倣学習だけでなく、失敗予測、回復方策、評価器の学習にも意味がある。ただし、これらは公表された内容から導ける利用可能性であり、同期・ラベル・エピソード構造が実ファイルに実装済みだと確認したものではない。

## 6.3 競技からデータセットまで

公表された説明が支える生成経路は、次の五段階である。

| 段階 | 入力・処理 | 出力 |
|---|---|---|
| 1. 準備・訓練 | 本番前の反復実行 | 調整途中を含む走行・作業記録 |
| 2. 正式競技 | 規則、環境、結果を伴う試合・試技 | 成功、失敗、得点、時間 |
| 3. 多種類の記録 | 映像、関節運動、機体状態 | 時系列の実行データ |
| 4. 処理・意味付け | 意図・行動、物体、境界条件の注釈 | 検索・学習できる意味情報 |
| 5. タスク化 | 場面、作業、技能、条件へ整理 | 12場面、44作業、100超の技能、1万超の詳細タスク |

訓練を含む点は重要である。競技本番の成功例だけでは、方策が改善される途中、調整に失敗した条件、同じ動作を繰り返したばらつきが残りにくい。準備段階からの記録は、完成した走行とそこへ至る試行を同じ研究対象へできる。

## 6.4 公開説明で分かること、技術文書が必要なこと

| 技術項目 | 公開説明で分かること | 公開技術文書では未提示 |
|---|---|---|
| 映像 | 多視点映像を含む | カメラ数、解像度、フレームレート、内部・外部カメラの区別 |
| 運動 | 関節運動情報を含む | 関節名、位置・速度・トルクの項目、単位 |
| 機体 | ロボット／機体状態を含む | コマンド、IMU、接触、電源・温度などの項目 |
| 時間 | 長いタスク軌跡を含む | タイムスタンプ、クロック、センサ同期方法 |
| 注釈 | 意味、行動、物体検出などを含む | スキーマ、注釈者、品質管理、信頼度 |
| 構成 | 12場面・44作業・100超技能・1万超詳細タスク | それぞれの対応表、訓練・検証・評価分割 |
| 配布物 | 2,500時間超と発表 | ファイル形式、容量、マニフェスト、版 |

この表は内容への否定ではなく、利用者がコードを書くために次に必要な仕様を示す。たとえば「関節運動情報」が位置だけか、速度・トルクまで含むかで学習できるモデルは変わる。多視点映像も、カメラ校正と同期情報があって初めて三次元の動作復元へ使える。

## 6.5 七つの共同発表者

データセットは、CCID、Beiao Group、北京人型ロボットイノベーションセンター、AGIBOT、Galbot、Spirit AI、Galaxeaの七者による共同発表だった。名称は公開ブランドへ統一したが、発表記事の列挙順を組織別のデータ量や責任順位とは解釈しない。[[1]](#ref-1)[[3]](#ref-3)

| 共同発表者 | 大会・データとの確認できる接点 | この資料だけでは確認できないこと |
|---|---|---|
| CCID | 産業研究機関として共同発表に参加 | 収録、注釈、品質評価、保管の担当範囲 |
| Beiao Group | 大会運営とアイスリボンの運用に関与し、共同発表に参加 | データ取得設備・出版作業の担当範囲 |
| 北京人型ロボットイノベーションセンター | Tiangong開発、競技参加・大学支援、共同発表 | 提供した時間数、種目、センサ、注釈量 |
| AGIBOT | ロボット・手先製品の開発、合同チーム、共同発表 | AGIBOT由来データの範囲と権利条件 |
| Galbot | ロボット開発と競技関係、共同発表 | Galbot由来データの範囲と処理方法 |
| Spirit AI | 公式チーム名に対応する競技参加関係、共同発表 | 法的主体ごとのデータ権利、注釈・保管の担当 |
| Galaxea | ロボット開発と共同発表 | 対象機体、収録量、公開作業の担当範囲 |

共同発表者ごとの収録時間、対象種目、注釈・保管・配布の担当範囲は公表されていないため、「七者が各自の全競技データを持ち寄った」とは書けない。確認できるのは、大会運営・産業研究と複数のロボット開発主体が一つのデータ成果を共同で発表したことまでである。Beiao Groupが大会運営に関与したことは同社の大会報告でも確認できる。[[4]](#ref-4)

2,500時間超という規模は、WHRGが競技を一過性の記録から学習資源へ変えようとしたことを示す。実際の研究資源になるかは、内容の豊かさに加えて、第三者がファイルと仕様へ到達できるかで決まる。次章ではその入口だけを独立に検証する。
